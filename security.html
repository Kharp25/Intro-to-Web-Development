IT 3203 / 04

Security and privacy

How browsers handle code and data from different websites.

Keeping sites apart

The same-origin policy limits how a script from one origin can interact with another origin’s resources. An origin is defined by a URL’s scheme, hostname, and port. Two pages can look related while still having different origins.

For example, https://example.com and https://example.org have different hosts. CORS lets a server explicitly allow certain cross-origin reads; it does not remove all browser security boundaries.

Sandboxing and process isolation

A sandbox restricts what a browser process can access. Multi-process architecture divides work among components, helping contain some crashes and security failures. Site isolation can add a process boundary between content from different sites.

These protections work together. No single boundary makes every page safe, and additional processes can increase memory use.

What the browser remembers

Cookies, caches, local storage, history, and permissions serve different purposes. A cookie might support a login session, while a cache stores reusable resources. Stored information can also contribute to tracking.

Security concerns unauthorized access and harm. Privacy also concerns how information is collected, shared, retained, and used. A secure connection alone does not tell you how a site will use your data.

Permissions and user control

Features such as location, camera, and microphone access involve sensitive information. Permission controls give users a way to decide which sites receive access. Private browsing changes how some local browsing data is retained; it does not make someone anonymous to every website or network.
