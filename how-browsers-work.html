How browsers work

Following a page from the address bar to the screen.

1. Request the resources

The browser interprets a URL to identify a resource. DNS can resolve its hostname to an IP address. The browser establishes or reuses a connection, then requests content through HTTP. HTTPS protects that communication using encryption.

The response often contains HTML. As the browser reads it, it discovers other resources to request, such as stylesheets, images, and scripts. Cached resources can reduce the amount of downloading needed.

2. Interpret the code

The browser parses HTML into the Document Object Model, or DOM. It processes CSS into the CSS Object Model, or CSSOM. Together, these structures help determine what content appears and how it looks.

JavaScript adds behavior. It can respond to user actions, request data, and change the DOM. Those changes can require the browser to update the screen.

3. Calculate layout and draw

  1. Style: determine which CSS rules apply to each element.
  2. Layout: calculate the sizes and positions of visible elements.
  3. Paint: draw text, borders, backgrounds, and images.
  4. Compositing: combine separately drawn layers when needed.

This is a simplified sequence. A browser can display part of a page before every resource finishes loading.

Browser and engine

A browser includes its interface, networking, storage, developer tools, and security controls. Its rendering engine handles much of the work of interpreting and displaying web content. Blink, WebKit, and Gecko are examples of browser engines.
