Performance and the future

Why a page can feel slow, even in a capable browser.

Where the time goes

A page can wait on DNS, a network connection, the server, or large resource downloads. Once the files arrive, parsing, JavaScript, layout, and painting also take time.

A visually simple page can still feel slow if scripts occupy the main thread. Repeated changes to element sizes can trigger more layout work. Performance depends on the page, the browser, the network, and the device.

Reducing unnecessary work

  • Use appropriately sized images so the browser downloads fewer bytes.
  • Reuse cached resources when they are still valid.
  • Limit expensive JavaScript and repeated layout changes.
  • Measure with browser developer tools before deciding what to optimize.

This project uses local assets and a shared stylesheet to keep its own pages lightweight.

Browsers as application platforms

Browsers support document editors, communication tools, graphics applications, and games. Web APIs expose capabilities that once required separate software. Each added capability raises questions about permissions, compatibility, and access to user information.

AI-assisted browsing

My research also considers AI-assisted browsing, including page summaries and help with tasks. These are possible uses rather than guarantees that every browser provides the same features.

Questions for future research include where page information is processed, what actions require user approval, and how users can check generated answers. A useful assistant still needs clear boundaries and a way for the user to correct mistakes.
